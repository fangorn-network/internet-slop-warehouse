# Dependency and save migration

The dependency is the supplied **RescueRelay 2.0.0**, vendored unchanged as `game/dependency-2.0.0.cjs`. The presentation now calls `Mission.advance(state, {x,y}, elapsedSeconds)`. The mission adapter calls `RescueRelay.advance` using its new object input and `{distance, clamped}` result contract; removed `move` is never called. Integration uses ≤25ms steps with the same 250ms cap, normalized direction, original speed/radius/walls/bounds. A temporary dependency state suppresses the old tower-only extraction predicate so the extended mission waits for Vale. No code in the frozen v1 page is pointed to the new dependency.

RR1 still goes through the unmodified dependency loader. The exact player position and activated signal IDs survive; activated towers become repaired and their corresponding unique components become collected/consumed. New components for unrepaired towers remain available. Vale starts at the authored northeast location, stranded. Old `completed` survives as `legacyCompleted`, visibly labeled in the progress strip. New `completed` describes rescue extraction, so even a previously completed expedition has a remaining escort objective. The load message and persistent save-panel note explain this policy.

A valid legacy position might lie inside the newly introduced flood shutter. In that uncommon case, `gateGrace` allows the player to leave without teleporting; it expires permanently on exit. The shutter still needs the north relay for subsequent passage. The load notice explains this, and the grace state is portable and validated. All supplied fixtures preserve their position without needing this exception.

RR2 state is versioned at schema 2: player position, unique collected IDs, repaired IDs, Vale position/mode, rescue completion, old completion, and migration grace. **Inventory = collected minus repaired**. A repair requires its matching collected component and occurs once; repaired IDs must be a subset of collected IDs, so repeated load cannot duplicate inventory or install rewards. There are no score rewards. Follow/wait can only begin after all three repairs; extracted mode requires both people at extraction and all repairs. Uncontacted Vale must remain at the authored position. Wall/boundary, ID, duplicate, status, and completion inconsistencies reject. Parse or checksum failure also rejects before the UI replaces its existing state.

RR2 exports canonical field order and sorted ID arrays; loading/exporting is idempotent. Pause and held keys are session UI state: loads start resumed with no held input. NPC route waypoints are a derived cache, reconstructed from the saved physical position over the same local grid, with a safe recenter step inside the current cell. Wait/follow mode, actual position, and all mission progress persist. FNV-1a detects accidental corruption only; saves are editable and not authenticated or anti-cheat data.
